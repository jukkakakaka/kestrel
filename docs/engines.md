# 分析引擎与四关量化证伪体系

Kestrel 只有一个选股决策总开关：**设置 → 分析引擎 → 由谁产生建议**。`/advice` 操作建议页只有一个扫描主按钮，行为与文案严格跟随该开关，绝不同时并列两套相互打架的信号源。

## 三种选股引擎模式

### 1. 规则引擎（`agent.provider = rules`）

条件以声明式 JSON 定义（见 `/rules`），全部满足才触发信号；零外部依赖、毫秒级响应、100% 确定性可复现。

```
候选池 → 日线缓存 → 按周期折叠（2日/日/周/月）→ 历史前缀指标计算
      → 启用且未在当前周期证伪淘汰的规则 evaluate()
      → 得分 ≥ 门槛 → planning.build 生成含费可执行计划
```

每条规则在各周期上的实测证伪结论独立存档；在当前周期被判定为「无优势」亏损的规则会被扫描器自动跳过。

### 2. 大模型引擎（`agent.provider = llm`）

需要配置用户自有的 OpenAI 兼容接口（`agent.base_url`、`agent.model`、`agent.api_key`，支持 DeepSeek / OpenAI / 通义千问 / Kimi / Ollama 等）。

执行流水线：
1. `analyst.build_brief()` 组装结构化简报：最多 40 只候选股 × 18 项量价指标 + 账户可用现金与风控约束 + 当前持仓 + 每条内置规则在当前周期的实测证伪结论；
2. 大模型返回结构化 JSON 候选与逻辑阐述（`picks` + `market_view` + `pass_reason`）；
3. 本地 `validate_pick()` 逐条执行硬风控过滤，不合格项直接拒绝并携原因入库展示；
4. 本地 `planning` 根据账户单笔风险预算与真实市场手数规则独立计算股数——**模型给出的股数永远丢弃不用**；
5. 通过校验的计划以 `source='ai'` 入库，卡片展示模型名称、置信度与完整看多/风险逻辑。

### 3. WorkBuddy 异步文件队列（`agent.provider = workbuddy`）

面向无本地常驻 API 密钥、通过外部定时 Agent 消费文件队列的场景：

```
data/bridge/pending/<id>.json   Kestrel 写入分析简报与 JSON 输出契约
data/bridge/done/<id>.json      外部定时任务写入模型响应
data/bridge/archive/            已校验入库归档
data/bridge/failed/             格式或校验失败留档
```

设置 → 分析引擎页面会根据当前运行环境的数据目录自动生成两段可直接复制的定时任务提示词（分析队列消费、微信通知转发），无需手工拼接路径。

## 硬风控护栏（三种引擎共用，AI 不可绕过）

| 检查项 | 强制规则 |
|---|---|
| 候选白名单 | 标的代码必须存在于当次扫描简报候选池内，严禁模型幻觉编造代码 |
| 止损带宽约束 | 止损价必须低于入场价，且止损距离落在当前周期合法带宽内（日线/快线 `1.5%–15%`、周线 `3%–18%`、月线 `5%–30%`） |
| 净盈亏比门槛 | `(target − entry) / (entry − stop) ≥ 1.5` |
| 入场偏离约束 | 计划入场区间必须在最新现价 `±15%` 以内 |
| 行业集中度 | 同一行业持仓与在途建议不超过 `risk.max_per_sector` |
| 总仓位上限 | 在途建议叠加已有持仓总敞口不超过 `risk.max_total_exposure_pct` |
| 真实手数与现金可负担 | 计入券商规费与整手/科创板 `200+1`/碎股能力后，单手超风险预算或超可用现金直接拒绝并说明原因 |

`agent.daily_budget` 限制每日大模型调用上限；耗尽后**明确报错停止**，绝不静默退回规则引擎误导用户。

## 四关量化证伪流水线（`backtest.py` + `rules.py`）

为防止把历史过拟合或随机运气包装成「有效策略」，Kestrel 在 `/sim`（单标的深度检验）与 `/rules`（全池跨周期规则验证）中内置了严密的**四关统计证伪体系**：

### 回测底层防前视与摩擦建模（`services/backtest.py`）
- **次日开盘成交（`next_open=True`）**：所有技术指标严格在截止信号根 `bars[:i+1]` 的历史前缀上计算；第 `i` 根收盘触发信号后，统一按第 `i+1` 根**开盘价叠加单边滑点 `slippage_bps`**（默认 `10 bps`）成交。若次日大幅低开直接跌破止损位则放弃入场（计入 `skipped_gap_down`）；若最后一根 K 线刚出信号尚无次日开盘价，则单独输出 `pending_signal` 绝不虚构成交。
- **可配双边成本与核心风险指标**：支持自定义双边手续费率 `fee_bps`（默认 `20 bps` 即 `0.20%`）与单边滑点 `slippage_bps`；除胜率、期望 R 外，同步计算盈亏比因子 `profit_factor`、逐根持仓状态年化夏普率 `bar_sharpe` 以及 16 位 SHA-256 确定性指纹 `determinism_hash`。
- **`3×3` 参数高原稳健性热力图（`parameter_plateau`）**：围绕基准持仓上限 `max_hold`（低/中/高 3 档）与 ATR 止损倍数 `[1.5, 2.0, 2.5]` 构建 9 宫格邻域矩阵，自动识别策略处于**稳健高原（`plateau`）**、**过拟合孤立尖刺（`spike`）**还是**整体无优势（`weak`）**。

### 规则页 G1–G4 四关闯关状态（`services/rules.py`）
每条规则在 `/rules` 页面均展示四道递进证伪关卡徽标：

1. **G1 扣费滑点筛选（`cost_sample`）**：在次日开盘成交并扣除真实手续费与滑点后，检验有效交易笔数是否达到最低统计门槛（`MIN_TRADES = 12`）且平均期望 `avg_r > 0`。
2. **G2 多折滚动前推（`walk_forward`）**：将历史区间切分为多个时间折（Folds），逐折对比策略平均收益与「同期同入场点、不设止损持有相同根数」基准的超额优势及正收益折占比。
3. **G3 置换显著性检验（`permutation`）**：使用固定随机种子（`seed=42`, `n_perms=500`，单次耗时 `<150ms`）对交易与基准序列做蒙特卡洛置换检验计算 `p` 值。**降级铁律**：即使 G1/G2 显示正收益，只要置换检验 `p ≥ 0.10`（无法排除随机噪声），系统强制将该规则从「有优势」降级为「不稳定」（`downgraded_by_perm=True`）。
4. **G4 实盘偏离监控（`live_drift`）**：`live_drift_report()` 持续对比该规则在历史生成建议及用户真实已平仓台账中的实际平均 R 与历史回测期望 R；当实盘/纸面跟踪样本 `≥ 3` 笔且显著跑输回测预期时，规则卡片自动亮起**表现偏离预警横幅**提醒复查失效风险。

## 右侧炒股 Agent（Copilot）的证据边界

右侧 `380px` 炒股顾问抽屉（`services/copilot.py`）与扫描选股引擎职责分离：它不直接生成入库建议单，而是作为实盘伴随问答顾问。每次对话自动注入：
- 账户实时总资产、可用现金、在持仓位（含成本、现价、止损距离、A 股 `T+1` 锁定状态）与活跃建议；
- 各策略最新的四关量化证伪摘要 `strategy_falsification`（含期望 R、置换检验 `p` 值与实盘偏离状态）。

System Prompt 与本地正则守卫双重约束：**严禁回答股票交易与 Kestrel 以外的无关话题，且严禁在缺少验证数据时编造胜率、夏普率或回测收益数字。**
