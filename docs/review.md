# Kestrel 手工交易审查与开源对照

一次交易需要回答三件事。为什么现在值得做，券商实际上成交了什么，把实际结果复盘后是否还值得沿用这个方法。Kestrel 用行情、策略和账户预算生成计划，由用户在券商确认委托及成交，台账以成交事实更新资金和持仓。

## 开源项目带来的改动

| 项目 | 做法与 Kestrel 中的落地 |
| --- | --- |
| [QuantConnect LEAN](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts) | 委托和成交分开，并处理部分成交与陈旧行情。Kestrel 要求输入实际成交价、数量。一条建议可记多次成交，界面显示累计数量和加权均价，扫描明确跳过陈旧日线。 |
| [Freqtrade](https://www.freqtrade.io/en/stable/lookahead-analysis/) | 将基准回测和切片运行对比，寻找未来数据泄漏。Kestrel 新增前缀回归测试，验证拼接后续行情后，截止点之前已完成的成交及逐根收益不变。 |
| [Microsoft Qlib](https://qlib.readthedocs.io/en/latest/component/workflow.html) | 将实验参数、结果和回溯记录关联。Kestrel 的回测指纹覆盖整个输入行情序列、参数与逐笔结果，检测同一日期范围内的数据修订。 |
| [Portfolio Performance](https://help.portfolio-performance.info/en/reference/transaction/buy-sell/) | 逐笔记录买卖、股数、金额和费用，并联动持仓与现金。Kestrel 的手工录入、签名回执和指定批次卖出共享记账逻辑，同一提交可安全重试，卖出费用为整笔成交做精确拆分。 |

## 运行时优先级

- **数据有效性**。规则扫描与 AI 计划都要求最近已收盘日的行情。某市场数据不足时，周期顾问回退到资金与费用依据。
- **计划适配性**。计划的风险金额、股数与保本价依据币种换算、费用、持仓和券商能力计算。市场建议使用启发式门槛，周期建议使用样本广度、波动和费用比较。
- **成交真实性**。建议价格和股数留在快照。记账按实际价格、数量、费用和交易日期，资金余额由台账推导。历史补录时检查成交日与可用持仓。重复提交同一请求可重放原结果。
- **学习主动权**。基本操作可直接照做。有兴趣时再开启计划解释、术语、风险与部分成交练习以及模拟页。

## 仍需验证的边界

- 公开行情可能延时、缺失或修订。市场假日是内置数据，对临时停市和提前收盘的覆盖有限。
- 回测使用当前候选池，可能存在幸存者偏差。当前撮合是基于 K 线的假设模型，成交量、买卖队列、停牌和盘中路径都可能改变真实结果。固定参考汇率也会影响跨币种收益估算。
- 批量导入的重试编号只覆盖一次提交。对一个历史文件在不同会话中再次导入前，应在券商记录和台账核对重复行。
- 公开来源、模拟和测试只验证软件行为。策略在真实账户的表现需要另有时间跨度足够的样本和可核对的券商数据。
